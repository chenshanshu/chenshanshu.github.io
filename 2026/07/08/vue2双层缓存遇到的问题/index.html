vue2双层缓存遇到的问题
chenshanshu Lv4
  2026-07-08 20:24:55 2026-07-08 20:24  
  • vue keep-alive 

背景

监控模块大致是这样结构：

外层缓存布局，是因为列表进的是 /monitor 外面的详情；不冻布局的话，出模块后内层叶子实例一起没了，分页列表和滚动位置就回不来。

内层再缓存叶子页，用来做模块内 Tab 互切、以及「列表 → 站外详情 → 返回」时的现场恢复。

遇到的问题

从消息等站外页，深链进入监控的另一个子路由时（例如离开时是 /monitor/overview，再进 /monitor/report-detail）：

  • 顶栏标题、底栏显隐正常（它们直接读 $route）
  • router-view 的 :key 日志也已经是新路由
  • 主体内容仍是离开前那一页（比如还是 overview）

原因可以概括成：

  1. App 层用固定 key 复用了同一个 MonitorLayout 实例（不会重新 mounted）
  2. 布局失活期间，内层 router-view 随路由的换页没有真正落到 DOM
  3. 唤醒后，内层 keep-alive 优先恢复失活前的「当前子树」，于是壳对了、内容还是旧的

另外：不要给 <keep-alive> 本身绑 :key 来强制重建——抽象组件这样换 key，后续 Tab 切换容易出现 monitor-body 空白。

解决方案

在现有约束下（详情在模块外 → 必须 App 缓存布局），采用：

同 path 返回 → 保留缓存；异 path 深链 → 重建内层缓存树

具体做法：

  1. beforeRouteLeave 用 from.path 记下离开时的子路由（不要在 deactivated 里读 $route，那时往往已经是目标页）
  2. activated 时对比：
    • 当前 path === 离开 path → 原样唤醒（列表/滚动还在）
    • 当前 path !== 离开 path → 重建内层
  3. 重建时：不要给 keep-alive 加 :key；给外面一层真实 DOM 换 key（或 v-if 卸载再挂载），例如：

异 path 时递增 innerCacheGeneration，整棵内层缓存树销毁后按当前 $route 重新挂载。

小结

场景 策略
列表 → 站外详情 → 返回同一列表 同 path，保留双层缓存
站外深链到另一子路由 异 path，重建内层
强制重建 换真实 DOM 包装层的 key，勿绑在 keep-alive 上

双层 keep-alive 不是设计错误，而是「站外详情要回列表」逼出来的；坑在冻住的布局被深链到别的子页时，内层不会自动跟上。把「同 path / 异 path」规则写死即可，不必给每个列表页单独做一整套状态持久化。
